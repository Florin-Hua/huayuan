# 第4阶段 · 上下文压缩

> 日期：2026-10-09
> 状态：代码与单元验收完成；真实验收继续受外部网络/API Key 限制
> 代码位置：`02-代码仓库/mini-agent/`

## 1. 阶段目标

把 Agent 从“无限累积消息”升级为有上下文预算的长任务执行系统：

1. 使用 tiktoken 估算当前上下文 token；
2. 默认 8192 token 预算，可通过 `.env` 配置；
3. 超预算时触发滚动摘要：最近 K=5 轮保留原文，更早轮次交给 LLM 压缩；
4. 工具输出超过 2000 字符时保留头 1000 + 尾 500 + 省略提示；
5. 注入顺序固定为：system → memory → compressed history → current input → recent turns；
6. 压缩开关可配置，每次压缩记录压缩前后 token 与被摘要轮数；
7. 关闭压缩且超预算时以 `CONTEXT_LIMIT` 优雅终止，不允许上下文无限膨胀。

## 3. 核心设计

### 3.1 Token 估算

`TokenEstimator` 使用 tiktoken 的 `cl100k_base` 编码：

- 文本 token：直接 encode；
- 消息 token：`role + content + tool name + tool_calls JSON`；
- 每条消息额外估算 4 token 结构开销；
- encoding 全局共享，避免每个 AgentCore 实例重复加载。

限制：Anthropic 与不同 OpenAI 模型的 tokenizer 并不完全一致，`cl100k_base` 用作统一预算估算，不作为计费依据。

### 3.2 上下文准备流程

每次调用模型前，AgentCore 都执行：

```text
history -> ContextManager.prepare(history)
         -> 未超预算：原样传入
         -> 超预算且开启压缩：滚动摘要
         -> 超预算且关闭压缩：ContextBudgetExceeded
```

压缩后的消息结构：

```text
system prompt
memory（阶段5接入）
[MiniAgent compressed history]
current user input
recent K rounds 原文
```

这样做的意图：

- system 规则始终保留；
- current input 不被摘要吞掉；
- 最近 K 轮保留原始工具调用与结果，保证模型仍有局部推理能力；
- memory 插入点在阶段5确定，避免后续重构注入顺序。

### 3.3 滚动摘要

一轮的定义：

```text
assistant(tool_calls) + 后续全部 tool result messages
```

压缩规则：

- 最近 K=5 轮保留原文；
- 更早轮次拼接成 transcript；
- 调用当前 ChatAdapter 生成不超过 300 字的摘要；
- 摘要要求保留任务目标、已尝试工具、关键结果、错误与未完成事项；
- 摘要调用不传入工具 schema，避免模型在压缩阶段发起新工具调用。

当前实现中摘要调用不计入主任务 `usage`，只记录压缩前后 token 统计。

### 3.4 工具输出截断

默认规则：

```text
输出 <= 2000 字符：原样保留
输出 > 2000 字符：前 1000 + 省略标记 + 后 500
```

实现位置在 AgentCore OBSERVE 阶段：

1. 先截断 `result.data`；
2. 再序列化为 tool message JSON；
3. JSON 外层增加 `truncated` 标记，让模型知道内容被截断；
4. Anthropic / OpenAI adapter 继续收到合法 JSON，不需要感知截断逻辑。

### 3.5 压缩统计与预算终止

每次压缩记录：

```python
CompressionStats(
    before_tokens=...,
    after_tokens=...,
    summarized_rounds=...,
    summarized_messages=...,
    enabled=True,
)
```

`AgentRun.compressions` 保存全部压缩记录，StepLog 增加 `COMPRESS` 状态，CLI 显示压缩次数。

关闭压缩时：

- 超预算直接抛出 `ContextBudgetExceeded`；
- AgentCore 捕获后返回 `RunStatus.CONTEXT_LIMIT`；
- answer 与 termination_reason 均说明上下文预算终止；
- 不伪造成功状态，也不让异常裸崩。

## 4. 配置方式

`.env`：

```env
CONTEXT_COMPRESSION_ENABLED=true
CONTEXT_TOKEN_BUDGET=8192
CONTEXT_RECENT_TURNS=5
CONTEXT_TOOL_OUTPUT_MAX_CHARS=2000
CONTEXT_TOOL_OUTPUT_HEAD_CHARS=1000
CONTEXT_TOOL_OUTPUT_TAIL_CHARS=500
```

如需验证预算终止，可临时设置：

```env
CONTEXT_COMPRESSION_ENABLED=false
CONTEXT_TOKEN_BUDGET=1000
```

## 6. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| token 估算 | tiktoken `cl100k_base` | 有真实 BPE 依据，比按字符数粗略估算更接近模型行为 |
| 压缩时机 | 每次 THINK 前检查 | 防止超预算请求发出去才失败 |
| 保留策略 | 最近 K 轮原文 + 早期摘要 | 兼顾长期目标与局部工具上下文 |
| 摘要执行者 | 当前 ChatAdapter | 不引入第二个模型配置；provider 适配层自动复用 |
| 工具输出截断 | OBSERVE 前截断 | 先控制上下文膨胀，再进入 adapter |
| 预算失败 | `CONTEXT_LIMIT` 终态 | 优雅终止且可测试，不把预算失败伪装成成功 |
| 摘要 usage | 暂不计入主 usage | 阶段4关注上下文 token；阶段6 Trace 再统一统计所有调用 |

## 8. 已知局限与下一阶段

- tiktoken 编码不是 Anthropic 官方 tokenizer，跨模型预算是估算；
- 摘要调用 token 未计入主任务 usage；
- 当前只压缩单次 run 的 ReAct history，跨会话记忆属于第5阶段；
- 若最近 K 轮本身超过预算，会触发 `CONTEXT_LIMIT`，这是预期保护行为；
- 第5阶段将实现 SQLite + 向量检索的长期记忆系统。
