## 3. 评测设计

### 3.1 评测口径

本阶段评测的是 **框架机制链路**，不是商业模型能力：

- `scripted-strong`：确定性策略，按数据集中的 `tool_rounds` 调用工具，然后输出任务标注的最终答案；
- `scripted-baseline`：确定性策略，不调用工具，直接输出 `baseline_final`；
- 两种策略均通过真实 `Agent`、`AgentCore`、`ToolRegistry`、`ContextManager` 与 `MemoryStore` 运行；
- 每个任务使用独立 sandbox，同一实验内共享 memory SQLite；
- runner 记录成功率、平均迭代、token、model calls、parse retries、压缩次数、保存记忆数、失败恢复率和逐任务 records。

因此 100% / 86.67% 等数字只能证明 MiniAgent 的循环、工具、错误回喂、压缩、记忆与统计链路有效，不能外推为 GPT / Claude / DeepSeek 的真实准确率。

## 4. 消融结果

| 模型策略 | 压缩 | 记忆 | 成功率 | 平均迭代 | 平均 token | 失败恢复率 |
|---|---:|---:|---:|---:|---:|---:|
| scripted-strong | ON | ON | 100.00% | 2.40 | 417.5 | 100.00% |
| scripted-strong | ON | OFF | 96.67% | 2.40 | 326.4 | 100.00% |
| scripted-strong | OFF | ON | 86.67% | 2.27 | 325.0 | 100.00% |
| scripted-strong | OFF | OFF | 83.33% | 2.27 | 245.7 | 100.00% |
| scripted-baseline | ON | ON | 6.67% | 1.00 | 173.8 | 0.00% |
| scripted-baseline | ON | OFF | 3.33% | 1.00 | 84.6 | 0.00% |
| scripted-baseline | OFF | ON | 6.67% | 1.00 | 173.8 | 0.00% |
| scripted-baseline | OFF | OFF | 3.33% | 1.00 | 84.6 | 0.00% |

关键结论：

1. **上下文压缩**：4 条长上下文任务从 0/4 变为 4/4，但平均 token 由 325.0 增至 417.5，说明摘要调用有额外成本；
2. **记忆系统**：关闭后 SB022 失败，总成功率从 100% 降至 96.67%，证明记忆检索和注入链路有效，但样本量不足以外推泛化收益；
3. **工具执行**：baseline 仅 6.67%，strong 达到 100%，说明结果主要来自工具 observation 而非模型猜答案；
4. **失败恢复**：8 条失败注入任务全部先收到 `ok=false` 再调整策略，恢复率 100%。

## 5. GAIA 无法下载的原因

- GAIA 官方数据集 `gaia-benchmark/GAIA` 是 HuggingFace gated dataset；
- 本机没有 `HF_TOKEN`，请求返回 `GatedRepo`；
- 项目不允许复制未授权 validation 内容，也不允许伪造 GAIA 指标；
- 因此 `gaia_subset.json` 保存访问状态、目标规模和筛选标准，`tasks` 为空；
- `select_gaia.py` 支持用户获得授权并自行下载 validation JSONL 后，在本地生成 text-only 子集。

## 6. 真实模型不可用的原因

- OpenAI key 已配置，但当前环境访问 `api.openai.com` 超时，真实调用返回 `APITimeoutError`；
- Anthropic 网络可达，但没有有效 `ANTHROPIC_API_KEY`；
- 供应商协议转换与 Agent 集成已由 fake client、录制 fixture 和 scripted adapter 测试覆盖；
- 本阶段没有用 scripted 结果冒充真实供应商调用。

## 7. 关键决策

| 决策 | 理由 |
|---|---|
| 使用 scripted policy 而非强行调用真实 API | 保证评测离线可复现，并明确区分“框架机制评测”与“模型能力评测” |
| 自建 30 条任务而非伪造 GAIA | 在授权缺失时保持数据合规与报告可信度 |
| 四组 strong 消融 + 四组 baseline 对照 | 能同时评估压缩、记忆、工具路径和失败恢复 |
| token / model calls 使用单任务差值 | 避免跨任务累计值污染指标；包含主循环、压缩和记忆抽取调用 |
| 将 eval results JSON 入库 | 可复现实验原始记录，且不包含密钥或本地运行数据 |
| GAIA 只保留 manifest 与选择脚本 | 尊重 gated dataset，同时说明后续补测路径 |

## 10. 已知局限

1. 阶段8是 scripted 框架评测，真实商业模型准确率未测，OpenAI 网络与 Anthropic key 是外部限制；
2. GAIA gated，未获得授权前没有公开基准成绩；
3. 默认 HashingEmbedder 语义能力有限，记忆泛化样本量很小；
4. 没有 checkpoint 恢复和流式输出；
5. MCP 当前只支持 stdio 的 `tools/list` / `tools/call`，未实现 sampling、roots、resource 写入等高级能力；
6. 工具超时依赖线程池，Python 线程超时后无法强制终止底层调用；
7. 多 MCP server 场景仍是一个 server 一个后台线程，尚未共享事件循环。

## 11. 最终结论

MiniAgent 已完成第0至第8阶段目标：从总体设计、最小 ReAct 闭环、工具系统、多模型适配、上下文压缩、记忆、健壮性与 Trace、MCP 兼容，到评测与交付，形成一套可解释、可测试、可复现的小型 Agent 框架。项目不追求替代生产级框架，而是保留一个清晰的 baseline 和学习型工程实现。
