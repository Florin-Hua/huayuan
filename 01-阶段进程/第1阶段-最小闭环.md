# 第1阶段 · 最小闭环

> 日期：2026-09-16
> 状态：代码与单元验收完成；真实验收因 OpenAI 请求超时待手动重试
> 代码位置：`02-代码仓库/mini-agent/`

## 1. 阶段目标

在不使用 LangChain / LlamaIndex / AutoGen 等框架的前提下，完成一个可运行、可测试、可观察的最小 ReAct Agent：

1. 能接收一个自然语言任务；
2. 能把任务交给模型并解析出工具调用；
3. 能执行内置工具并把结果回喂模型；
4. 能在工具失败后继续运行，让模型自行调整；
5. 能得到结构化终态：`SUCCESS` / `MAX_ITER` / `PARSE_ERROR`；
6. 能通过 CLI 展示执行轨迹。

## 3. 核心设计

### 3.1 状态机

```text
user task
  -> THINK：adapter.chat(messages, TOOL_SCHEMAS)
      -> 无 tool_calls：END，状态 SUCCESS
      -> 有 tool_calls：ACT
  -> ACT：execute_tool(call, sandbox)
  -> OBSERVE：工具结果 JSON 作为 tool 消息回喂
  -> 回到 THINK
  -> 达到 max_iterations：END，状态 MAX_ITER
```

模型调用抛出的异常不会导致 CLI 崩溃，而是转成 `PARSE_ERROR` 终态；工具异常不会终止循环，而是以结构化错误回喂模型。

### 3.2 工具安全边界

- `calculator`：
  - 不使用 `eval` / `exec`；
  - 使用 Python `ast` 解析并递归校验节点白名单；
  - 仅允许数值常量、`+ - * / // % **`、一元正负号；
  - 指数绝对值超过 1000 时拒绝。
- `read_text_file`：
  - 相对路径基于 `sandbox` 解析；
  - 使用 `Path.resolve()` + `is_relative_to()` 防止 `../` 逃逸；
  - 只读取 UTF-8 文本文件；
  - 超过 8000 字符截断并标记 `truncated`。

### 3.3 依赖边界

- `core` 不直接 import OpenAI SDK，只依赖 `ChatAdapter` 协议；
- `adapters` 负责把供应商格式转换为内部 `Message` / `ModelResponse`；
- `tools` 不感知模型，只接收 `ToolCall`；
- 阶段3扩展多模型时，只需新增 adapter，不改核心循环。

## 5. 关键决策

1. **先用 for/else 手写循环**：让迭代、终态、轨迹的因果链完全可见，之后再抽象执行器。
2. **工具错误必须回喂**：这是 Agent 与普通函数调用的核心差异，也是阶段1最重要的自愈能力。
3. **OpenAI 适配器只做格式转换**：保持 core 模型无关，为阶段3多模型适配留边界。
4. **calculator 使用 AST 白名单而不是正则替换**：防止任意代码执行；比“黑名单过滤 eval”更安全。
5. **fixture `data/notes.txt` 不入库**：`.gitignore` 已忽略 `data/`，避免运行数据污染仓库。
6. **本阶段不实现 `@tool` 装饰器**：工具注册系统属于阶段2，避免提前复杂化。
