## 3. 核心设计

### 3.1 工具定义

`ToolDefinition` 保存：

- `name`
- `description`
- OpenAI function calling 格式的 `parameters`
- Python 执行函数
- Pydantic 参数模型
- `timeout_seconds`
- `requires_sandbox`

装饰器支持两种用法：

```python
# 方式一：显式 Pydantic 参数模型（推荐，schema 描述最清楚）
class EchoInput(BaseModel):
    message: str = Field(description="要原样返回的文本")

@tool(EchoInput)
def echo_tool(message: str) -> dict:
    """返回输入文本。"""
    return {"message": message}
```

```python
# 方式二：没有显式模型时，从函数签名自动生成
@tool
def upper_case(text: str) -> str:
    """把文本转为大写。"""
    return text.upper()
```

### 3.2 ToolRegistry

核心职责：

1. `register()`：注册工具，重复注册直接报错；
2. `schemas`：输出全部工具 schema，供模型 function calling 使用；
3. `execute()`：
   - 幻觉工具：返回 `unknown tool: ...`
   - 参数错误：Pydantic 校验失败，返回 `ToolInputError`
   - 执行异常：返回 `异常类型: 信息`
   - 超时：返回 `ToolTimeoutError`
4. 所有结果统一封装为 `ToolResult`，再由核心循环回喂模型。

### 3.3 超时策略

使用 `ThreadPoolExecutor + future.result(timeout=...)`：

- 优点：跨平台，Windows 可用，不引入进程开销；
- 局限：Python 线程无法被强制杀死，超时后调用方会立即返回，但线程可能继续运行到结束；
- 阶段6如需更强隔离，可升级为进程池或独立 worker。

### 3.4 AgentCore 集成

第1阶段：

```python
result = execute_tool(call, sandbox)
```

第2阶段：

```python
result = self.registry.execute(call, sandbox)
```

核心循环不再知道具体工具名，也不再用 `if/elif` 分发。新增工具只需要注册，不需要修改 loop。

### 3.5 自定义工具 API

```python
from mini_agent import Agent, tool

@tool
def shout(text: str) -> str:
    """把文本转为大写。"""
    return text.upper()

agent = Agent(tools=[shout], sandbox_dir="data")
result = agent.run("把 hello 转成大写")
```

如需沙箱，在函数签名中加入 `sandbox: Path`，装饰器会自动识别并注入，且不会把 `sandbox` 暴露给模型。

### 4.2 真实验收（网络阻断）

尝试执行：

```powershell
.venv\Scripts\python.exe -m mini_agent.cli run "读取 notes.txt，统计行数，把行数写入 result.txt，再读回 result.txt 验证" --sandbox .
```

两次均在 `THINK` 阶段约 20 秒后返回：

```text

```

随后用不带密钥的请求检查网络：

```powershell
curl.exe -I --max-time 20 https://api.openai.com/v1/models
```

结果：

```text

```

结论：当前环境无法连接 `api.openai.com`，请求尚未到达 OpenAI 服务，因此不是密钥或模型配置错误。MiniAgent 按设计将模型调用异常转为 `PARSE_ERROR`，未崩溃。

网络恢复后建议使用以下命令重试（`--sandbox data` 确保 `notes.txt` 与 `result.txt` 都在 gitignored 的 data 目录内）：

```powershell

```

## 5. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| schema 来源 | Pydantic 参数模型 | 类型、必填、描述由一处声明生成，避免手写 JSON Schema 漂移 |
| 调度方式 | 注册表 + 方法分发 | 新增工具零修改核心循环，符合第0阶段模块依赖规则 |
| 错误处理 | 全部归一化为 `ToolResult` | 模型能看到错误并自愈，测试也能统一断言 |
| 超时实现 | 线程池 future timeout | Windows 兼容；比信号量方案更简单 |
| 并发执行 | 暂不做 | 阶段2明确单线程即可，避免 scope 蔓延 |
| `mock_web_search` | 固定 fixture | 测试可复现、不访问网络、不依赖外部搜索服务 |
