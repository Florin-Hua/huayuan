# 第9阶段 · 本地可视化界面

- 阶段编号：第9阶段
- 状态：✅ 已完成
- 完成日期：2026-10-09
- 版本：MiniAgent 0.9.0
- 目标：为已完成的 MiniAgent 提供一个本地可视化 Web 控制台，能直接运行任务、查看 ReAct 轨迹、管理长期记忆并回看历史 Trace。

## 1. 阶段目标

第0-8阶段已经完成 CLI、Python API、ReAct、工具、模型适配、上下文压缩、记忆、Trace、MCP 与评测闭环。第9阶段补上个人使用中最直接的体验缺口：不用命令行也能观察 Agent 的完整执行过程。

验收用户故事：

1. 我在浏览器输入一个任务，可以看到最终答案与 status / iterations / tokens / compression 指标；
2. 我能逐步查看 THINK / ACT / OBSERVE / COMPRESS / RETRY / GUARD / END 轨迹；
3. 我能搜索、刷新、删除长期记忆；
4. 我能查看历史 run，点击某条历史就能回看当时的 Trace；
5. 我可以临时覆盖 provider、model、最大迭代数，并选择是否启用内置 MCP；
6. API key 始终留在本地 `.env`，不会出现在接口响应或页面里。

## 2. 技术方案与关键决策

### 2.1 为什么不用 FastAPI / Streamlit / React

| 方案 | 判断 |
|---|---|
| FastAPI | 生态成熟，但会新增路由、Pydantic HTTP 层与 ASGI 部署概念；本项目 API 只有 8 条，收益有限 |
| Streamlit | 最快出 Demo，但状态模型、请求粒度和页面结构会被框架接管，不利于解释 Agent 执行链路 |
| React / npm | 前端生态强，但会引入构建链与依赖锁定；当前页面只有一个控制台，不需要组件化框架 |
| **Python 标准库 + 原生前端（采用）** | 零新增依赖、零构建步骤、代码可控，也符合本项目“每一层都能解释”的叙事 |

最终实现：

- 后端：`http.server.ThreadingHTTPServer` + `BaseHTTPRequestHandler`；
- 前端：原生 HTML / CSS / JavaScript；
- 业务入口：复用 `Agent`、`MemoryStore`、`TraceStore`，Web 层只做路由与序列化；
- 依赖：不新增任何 runtime dependency，不需要 npm install。

### 2.2 架构

```text
Browser
  │  http://127.0.0.1:8765
  ▼
MiniAgentRequestHandler        # HTTP 请求解析、JSON 读取、响应头
  │
MiniAgentWebApp                # 纯 Python API 路由层，可脱离 HTTP 单测
  ├─ /api/run            → Agent.run(task) → AgentRun
  ├─ /api/memories       → MemoryStore
  ├─ /api/runs           → TraceStore
  └─ /api/config         → 只返回非敏感配置
  ▼
web/index.html + styles.css + app.js
```

`MiniAgentWebApp` 不继承 HTTP handler，而是暴露 `route_api()` / `route_static()`。这带来两个好处：

1. 单元测试不需要真正启动 socket；
2. HTTP 解析、业务路由、Agent 执行的职责清晰分离。

## 3. API 设计

| 方法 | 路由 | 功能 |
|---|---|---|
| GET | `/api/config` | 返回 provider、model、memory / trace / compression 状态、工具列表；不返回 API key |
| POST | `/api/run` | 运行任务，支持 provider / model / maxIterations / useBuiltinMcp |
| GET | `/api/memories` | 获取长期记忆列表 |
| POST | `/api/memories/search` | 按 query / topK 搜索记忆 |
| DELETE | `/api/memories/{id}` | 删除指定记忆 |
| GET | `/api/runs` | 获取历史 run 列表 |
| GET | `/api/runs/{run_id}` | 获取某个 run 的 Trace |
| GET | `/`、`/styles.css`、`/app.js` | 提供白名单静态文件 |

`POST /api/run` 返回 `AgentRun` 的 JSON 序列化结果。`Usage.total` 是 Pydantic property，`model_dump()` 不会自动带出，因此 `serialize_run()` 会显式补齐：

```python
payload = run.model_dump(mode="json")
payload["usage"]["total"] = run.usage.total
```

这样前端可以稳定显示总 token 消耗。

## 4. UI 功能

页面分为四个主区域：

1. **任务运行**
   - 任务输入框；
   - 文件总结、计算、写入记忆、MCP 示例四个快捷任务；
   - provider / model / 最大迭代覆盖；
   - 内置 MCP 开关；
   - 运行状态、最终答案与指标卡。

2. **执行轨迹**
   - 表格展示轮次、状态、工具名、参数、结果、耗时、token 与说明；
   - 前端对所有动态文本做 HTML escape，避免把模型输出当 HTML 渲染。

3. **长期记忆**
   - 列表、搜索、刷新、删除；
   - 记忆开关关闭时显示明确错误。

4. **历史运行**
   - 展示 run_id、状态、迭代数、token 与开始时间；
   - 点击历史 run 会调用 `/api/runs/{run_id}`，把当时 Trace 回放到当前界面。

## 5. 安全与健壮性设计

1. **默认只绑定本机**：`127.0.0.1:8765`，不默认暴露局域网或公网；
2. **密钥不出口**：`/api/config` 只返回 provider、model 和功能开关，不返回 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY`；
3. **请求体限制**：JSON body 最大 64KB；
4. **输入校验**：
   - task 非空且不超过 4000 字符；
   - provider 只允许 `openai` / `anthropic`；
   - maxIterations 必须是 1-20 的整数；
   - model 字符串最多 100 字符；
5. **MCP 信任边界**：UI 不接受任意 server 命令，只能勾选内置 `mini_agent.mcp_server`；
6. **静态文件安全**：拒绝路径穿越，仅允许 `web/` 内白名单后缀；
7. **异常边界**：模型或 Agent 异常返回结构化 JSON 500，不让 HTTP server 直接崩溃；
8. **无跨域开放**：当前面向本地同源页面，没有配置公网 CORS。

## 6. Provider 兼容补充

`Settings.normalize_provider()` 增加了 OpenAI 兼容 provider 别名：

```text
qwen / 千问 / deepseek / moonshot / glm / ollama → openai
```

也就是说，本地 `.env` 可以继续使用 OpenAI 兼容服务的 provider 名称，内部统一归一化为 `openai` adapter。该逻辑不改变 Anthropic 原生 adapter 的行为。

阶段0的 3000 行预算针对 Agent 核心运行时，不含 tests / eval / docs / 示例。第9阶段把 Web UI 视为额外可视化层：Agent 运行时仍为 2373 非空行，未超预算；若把可视化层也计入 `src/mini_agent/` 总非空行数，则为 3199 行，必须如实说明超支，而不是隐藏。

## 9. 已知局限

1. Web UI 没有登录鉴权，只适合本机使用，不能直接部署到公网；
2. 没有流式输出，任务运行期间只能显示 busy 状态；
3. `/api/run` 是同步执行，长任务会占用一个请求线程；
4. provider UI 只暴露内部 `openai` / `anthropic`，OpenAI 兼容服务通过 `.env` 的 base_url 和 model 配置；
5. 历史记录来自 SQLite Trace，删除 Trace 数据后页面自然无法回看；
6. 没有做多用户、权限、审计和 HTTPS。

## 10. 结论

第9阶段完成。MiniAgent 现在有三类使用入口：CLI、Python API 和本地可视化控制台。Web 层没有引入新依赖，也没有把 API key 暴露到前端；更重要的是，它把原来只在终端里可见的 ReAct 状态机、工具调用、记忆和 Trace 变成了可点击、可回看、可解释的界面。

后续可选增强：登录鉴权、SSE 流式输出、Trace 过滤器、可视化 token 曲线、任务模板管理。
